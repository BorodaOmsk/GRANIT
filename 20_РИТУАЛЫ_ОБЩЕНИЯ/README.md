# Ритуалы общения с заказчиком

Практическое дополнение к [методологии ГРАНИТ](../README.md). Методология даёт **механизмы** (Единое окно, CCB, буфер, письменная фиксация). Эти документы дают **поведение** — повторяемые события общения и готовые фразы, без которых механизмы не работают.

---

## Зачем это нужно

ГРАНИТ держится на дисциплине заказчика: он назначил одного куратора, приносит задачи через Единое окно, принимает решения на CCB под протокол. Но заказчик не обязан знать эти правила и почти никогда не хочет их соблюдать по своей воле. Его естественное поведение — принести задачу в чате, надавить «надо вчера», сказать «сделайте всё и в срок».

**Ритуал** — это способ превратить правила методологии в привычку заказчика через регулярность и предсказуемость. Не «объяснить один раз», а «повторять в одном формате, пока не станет нормой».

> Главная мысль: заказчик соблюдает процесс не потому, что прочитал регламент, а потому что каждую неделю в одно и то же время происходит одно и то же, и он к этому привыкает. Разрушение ритма = разрушение методологии.

## Три уровня ритуалов

```
┌──────────────────────────────────────────────┐
│  УСТАНОВОЧНЫЙ (один раз, на старте)            │
│  Договориться о правилах игры до первой задачи │  → 01
└──────────────────────────────────────────────┘
                    │
                    ▼
┌──────────────────────────────────────────────┐
│  РЕГУЛЯРНЫЕ (по расписанию, всегда одинаково)   │
│  CCB • демо • еженедельный статус               │  → 02
└──────────────────────────────────────────────┘
                    │
                    ▼
┌──────────────────────────────────────────────┐
│  СИТУАТИВНЫЕ (по триггеру, по скрипту)          │
│  Вброс • давление • плохая новость • эскалация  │  → 03, 04
└──────────────────────────────────────────────┘
```

## Золотые правила общения (TL;DR)

1. **Регулярность важнее содержания.** Лучше короткий статус каждую пятницу, чем подробный отчёт раз в месяц. Ритм = доверие.
2. **Никогда не говори «нет» — говори «да, и вот цена».** Отказ провоцирует обход процесса. Выбор вариантов держит заказчика внутри процесса.
3. **Всё, что решено устно, не решено.** После любого разговора — письмо-подтверждение. Нет письма — нет решения.
4. **Показывай поток, а не защищайся.** Реестр изменений на экране отрезвляет сильнее любых аргументов: «вы принесли 15 задач сверх плана за месяц».
5. **Плохую новость — первым и рано.** Заказчик, узнавший о риске заранее, помогает. Узнавший поздно — штрафует.
6. **Один голос заказчику — один куратор проекту.** Всё остальное вежливо возвращается в Единое окно.
