# Методология ГРАНИТ

**ГРАНИТ** — гибридная методология управления разработкой для компаний с государственным участием, работающих по госконтрактам с жёсткими сроками.

> **ГРАНИТ** = **Г**осконтрактная **Р**егламентированно-**А**даптивная методология с управлением **Н**еплановыми задачами, **И**теративным исполнением и контролем **Т**ребований.

Название отражает суть: снаружи — гранитная твёрдость обязательств по контракту (даты, объём, документы), внутри — гибкое адаптивное исполнение.

---

## Зачем нужна ГРАНИТ

Классические методологии по отдельности не решают проблему госзаказчика:

| Методология | Что даёт | Чего не хватает для госконтрактов |
|-------------|----------|-----------------------------------|
| **Waterfall** | Фиксированные вехи, документация, соответствие регламентам, приёмка по этапам | Не умеет поглощать поток внеплановых задач без срыва плана |
| **Agile / Scrum** | Быстрая адаптация, обратная связь, приоритизация | Нет жёстких контрактных дат и формальной приёмки, «расплывается» объём |
| **SAFe** | Синхронизация нескольких команд, планирование инкремента, управление зависимостями | Тяжёлый, избыточный для одной-двух команд, дорогой во внедрении |

**ГРАНИТ** соединяет их: контрактный контур (Waterfall + гейты соответствия) + исполнительный контур (Agile-итерации) + координационный контур (лёгкий SAFe: единое планирование инкремента), а сверху — **контур управления изменениями**, который поглощает вбросы заказчика без срыва вех.

---

## Ключевая идея: два потока работ и защитный буфер

Вся работа делится на два потока:

1. **Контрактный поток (Plan)** — то, что зафиксировано в госконтракте: объём, вехи, даты приёмки. Защищён и не двигается без официального изменения контракта.
2. **Поток вбросов (Inflow)** — внеплановые задачи заказчика. Проходит через **Единое окно изменений** и не может напрямую забрать время у контрактного потока.

Между ними — **защитный буфер мощности** (обычно 15–25% ёмкости команды в каждой итерации), зарезервированный под неизбежные вбросы. Всё, что не влезает в буфер, идёт через формальную процедуру: либо в следующий инкремент, либо оформляется как изменение контракта (сдвиг сроков/объёма).

```
        ┌───────────────────────────────────────────────┐
        │            КОНТРАКТНЫЙ КОНТУР                   │
        │  Вехи • Даты приёмки • Документы • Гейты        │  ← Waterfall
        └───────────────────────────────────────────────┘
                 │ декомпозиция на инкременты
                 ▼
        ┌───────────────────────────────────────────────┐
        │           КООРДИНАЦИОННЫЙ КОНТУР                │
        │  Планирование инкремента (PI) • Зависимости    │  ← лёгкий SAFe
        └───────────────────────────────────────────────┘
                 │ декомпозиция на итерации (2 недели)
                 ▼
        ┌───────────────────────────────────────────────┐
        │           ИСПОЛНИТЕЛЬНЫЙ КОНТУР                 │
        │  Итерации • Доска • Ежедневки • Демо • Ретро    │  ← Agile
        │                                                 │
        │   [ Контрактный поток ]  [ БУФЕР вбросов 15-25% ]│
        └───────────────────────────────────────────────┘
                 ▲
                 │ прошедшие фильтр вбросы
        ┌───────────────────────────────────────────────┐
        │       КОНТУР УПРАВЛЕНИЯ ИЗМЕНЕНИЯМИ             │
        │  Единое окно • Классификация • Совет по         │
        │  изменениям (CCB) • Влияние на контракт         │
        └───────────────────────────────────────────────┘

   ┌─────────── СКВОЗНОЙ КОНТУР УСТОЙЧИВОСТИ ───────────┐
   │  Качество/DoD • Риски • Стейкхолдеры • Знания •    │
   │  Импортозамещение • Субподряд                      │
   │        (пронизывает все уровни от входа до сдачи)  │
   └───────────────────────────────────────────────────┘
```

Итого пять контуров: **контрактный** (Waterfall), **координационный** (лёгкий SAFe), **исполнительный** (Agile), **управления изменениями** (ядро против вбросов) и **сквозной контур устойчивости** (качество, риски, люди, окружение), который держит проект от предконтракта до гарантии.

## Быстрый старт (TL;DR)

1. Разложите госконтракт на **вехи** с датами приёмки (контрактный контур).
2. Разбейте каждую веху на **инкременты** по 8–10 недель (координационный контур).
3. Внутри инкремента работайте **двухнедельными итерациями** (исполнительный контур).
4. Зарезервируйте **15–25% ёмкости** команды под вбросы заказчика.
5. Заведите **Единое окно изменений**: ни одна внеплановая задача не идёт в работу мимо него.
6. Раз в неделю собирайте **Совет по изменениям (CCB)**: классифицируйте вбросы, решайте — буфер / следующий инкремент / изменение контракта.
7. Фиксируйте всё письменно: любое изменение объёма → протокол + оценка влияния на сроки.
