# Метрики ГРАНИТ

Метрики решают две задачи: удержать контрактные сроки и держать под контролем поток вбросов. Метрик немного — только те, что ведут к решениям.

---

## 1. Контрактное здоровье

### Прогноз по вехам (Milestone forecast)
Для каждой вехи: прогнозируемая дата завершения vs контрактная дата.
- 🟢 запас ≥ 10% срока
- 🟡 запас 0–10%
- 🔴 прогноз позже контрактной даты → немедленная эскалация на CCB

### Прогресс по вехам (план vs факт)
- **Плановый прогресс** vs **фактический** по объёму работ вехи.
- Индикатор отставания/опережения. Позволяет заказчику видеть реальность, а не обещания.

---

## 2. Поток вбросов (ядро ГРАНИТ)

### Частота вбросов
Количество зарегистрированных изменений за инкремент. Тренд важнее абсолюта: растёт — сигнал усилить работу с куратором заказчика.

### Расход буфера
```
Расход буфера (%) = использованная ёмкость буфера / выделенный буфер × 100%
```
- < 70% — буфер, возможно, завышен.
- 70–100% — здоровое состояние.
- > 100% — систематический перебор → пересмотр буфера и/или объёма контракта.

### Структура решений CCB
Доля вбросов по маршрутам: буфер / следующий инкремент / изменение контракта / отклонено.
- Большая доля «изменение контракта» → объём реально растёт, нужны допсоглашения.
- Большая доля «в буфер сейчас» → риск перегрузки текущего потока.

### Время до решения по вбросу (Change lead time)
От регистрации до решения CCB. Долго → заказчик недоволен реакцией; слишком быстро без оценки → риск непросчитанных обещаний.

---

## 3. Исполнительное здоровье

### Скорость команды (Velocity)
Средняя за инкремент, для прогноза. Смотрим тренд, не сравниваем команды между собой.

### Предсказуемость (Say/Do ratio)
```
Предсказуемость = выполненные обязательства / взятые обязательства × 100%
```
Цель — стабильно 80–100%. Низкая предсказуемость = планируем без учёта буфера или переоцениваем ёмкость.

### Техдолг
Объём и тренд реестра техдолга. Рост при активных вбросах — ожидаем, но должен гаситься.

---

## 4. Качество

- **Дефекты после приёмки** — попавшие к заказчику. Цель — снижение.
- **Возвраты на гейте соответствия** — сколько раз веха не прошла гейт с первого раза.

---

## 5. Риски, знания (устойчивость)

Метрики из специализированных контуров, которые тоже влияют на срок вехи:

- **Число 🔴-рисков** и **реализовавшихся рисков** — растёт → срыв ближе ([11](11_УПРАВЛЕНИЕ_РИСКАМИ.md)).
- **Модули с bus factor = 1** без плана — прямой кадровый риск сроков ([14](14_ЗНАНИЯ_И_КОМАНДА.md)).
- **Время прохождения задачи (lead/cycle time)** и **число задач «в работе»** — контроль WIP-дисциплины ([05](05_ПЛАНИРОВАНИЕ_И_БУФЕРЫ.md)).

## Панель здоровья процесса (dashboard)

Минимальный набор для одного экрана:

| Показатель | Норма | Действие при отклонении |
|-----------|-------|-------------------------|
| Прогноз ближайшей вехи | 🟢/🟡 | 🔴 → эскалация, пересмотр объёма |
| Расход буфера вбросов (по зонам) | 🟢/🟡 | 🔴/⚫ → допсоглашение/сокращение объёма |
| Расход проектного буфера сроков | 🟢/🟡 | 🔴/⚫ → эскалация, пересмотр вехи |
| Предсказуемость | 80–100% | <80% → пересмотр планирования |
| Частота вбросов (тренд) | стабильна/падает | рост → работа с куратором заказчика |
| Доля «изменение контракта» | — | рост → инициировать допсоглашения |
| 🔴-риски / bus factor = 1 | 0 без плана | есть → меры немедленно |

## Антипаттерны метрик

- **Не** используйте velocity как KPI сотрудников — убивает честную оценку, критичную для карточек влияния.
- **Не** прячьте расход буфера >100% — это ключевой ранний сигнал срыва.
- **Не** меряйте «занятость» людей вместо результата — в госконтракте важен результат к дате, а не загрузка.
- Метрика без решения бесполезна: если по показателю никто ничего не делает — уберите его.
